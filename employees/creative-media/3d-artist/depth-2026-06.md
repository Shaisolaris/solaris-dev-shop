# 3D Artist - Depth pass 2026-06-13 (methodology only, no code bundled)

## 1. Open PBR path upgraded: TRELLIS.2 (MIT)
Old tradeoff: TRELLIS = best geometry but geometry-only; Hunyuan3D-2.1 = real PBR but jurisdiction-limited (EU/UK/Korea excluded).
New: microsoft/TRELLIS.2 (MIT) adds full PBR materials via O-Voxel field-free sparse-voxel latents, with sharp features and complex topology.

Impact on the decision rules:
- Zero cost + GPU + PBR + ANY region (incl. EU/UK/Korea) -> TRELLIS.2 (MIT). This is now the default open PBR choice.
- Hunyuan3D-2.1 stays a valid option ONLY outside EU/UK/Korea; no longer the only open PBR route.
Self-host note: TRELLIS.2 runs on a 16GB+ NVIDIA GPU like the base model; meshes import into Blender via the backbone. No code is bundled into this employee; this is a self-host plan.

## 2. Rig stage upgraded: SkinTokens (UniRig successor)
VAST-AI-Research/SkinTokens (released 2026, ~79 stars, same authors as UniRig). Unifies skeleton prediction and skinning into ONE autoregressive sequence via learned discrete skin tokens. Reported +98-133% skinning accuracy and +17-22% bone-prediction accuracy over prior SOTA (incl. UniRig).
- When available and license-compatible, prefer SkinTokens over the two-stage UniRig flow for non-humanoid / mixed rigs.
- UniRig stays the documented fallback (mature CLI, 8GB+ VRAM, obj/fbx/glb/vrm).
- Mixamo stays the humanoid fast path.
Self-host note: GPU-local model; license not permissively confirmed at this pass, so treat as self-host methodology only, no code bundled.

## 3. Small-task / prototype lane
Not every request needs the full 5-stage game-ready pipeline. Triage up front:
- PROTOTYPE / blockout (greybox, gameplay test): generate -> Blender quick decimate -> export GLB. Skip rig, skip PBR, skip retopo. Mark deliverable "prototype, not final".
- SINGLE STATIC PROP, low stakes: generate -> Blender cleanup (decimate + Smart UV + scale/origin) -> GLB. Skip rig.
- FULL game-ready hero/character: the full pipeline (generate -> backbone -> rig -> texture -> import contract).
State which lane at the start so the poly budget and stage list are explicit.

## 4. Rendering / execution path (what is wired vs plan-only)
This employee is EXECUTION-DEPENDENT. It cannot itself run Blender or a GPU model; it drives them through MCP servers the host connects.
- WIRED when host connects: blender-mcp (owned backbone, runs bpy via execute_blender_code), Hyper3D Rodin + Hunyuan3D generation inside Blender, Poly Haven + Sketchfab asset pulls, ComfyUI (texture pass), Replicate/fal MCP (some hosted 3D-gen models).
- PLAN-ONLY until host provides GPU + model: TRELLIS / TRELLIS.2, Hunyuan3D-2.1/Paint, UniRig, SkinTokens (all local-GPU; no MCP, run via their CLI on a 16GB+/8GB+ NVIDIA box).
- PLAN-ONLY via Web Operator: Mixamo (browser auto-rig).
- KEY-GATED: Rodin/Tripo/Meshy commercial APIs need host-supplied keys; name the missing key and stop if absent.
Never fabricate a mesh/rig if the tool, key, or GPU is not connected; state exactly what is missing.

## 5. Pre-export gate (operationalized checklist)
The pre-export checklist in engine-import-contract.md is the release gate. Run it as an explicit pass/fail before any export; do not export on a fail.
G1 poly budget met (decimated/retopo'd to stated budget)
G2 UVs clean, no overlaps for baked maps
G3 scale 1u = 1m, transforms applied, origin set
G4 rig verified if applicable (pose-test a few bones), skin weights sane
G5 PBR set complete (basecolor/normal/roughness/metallic/AO), not a lone diffuse
G6 correct container: GLB static / FBX 2020 binary rigged
G7 clean import in target engine (test once)
Any fail -> fix and re-run the gate. This gate is the difference between game-ready and rework.
