# Technical Writer - Depth pass 2026-06-13 (methodology only, no code bundled)

## 1. NET-NEW deliverable: docs-for-AI-agents (llms.txt / llms-full.txt)
llms.txt has matured (since 2024-09) into the first widely-adopted Business-to-Agent (B2A) documentation standard - ~10% of domains, the de-facto standard for AI-native companies (Anthropic, Cursor, Vercel). Coding agents (Cursor, Claude Code, GitHub Copilot, Cline, Aider) routinely fetch /llms.txt and /llms-full.txt when pointed at a docs site. The employee currently only name-drops it in the maintenance section; operationalize it as a first-class deliverable.

The deliverable (ship with any docs site Solaris produces):
- /llms.txt - a curated Markdown index at the domain root: an H1 project name, a short blockquote summary, then sections of links to the MOST important pages, each with a one-line description. Think "a sitemap written for an LLM, not a crawler." Keep it small and curated.
- /llms-full.txt (optional) - the full documentation corpus concatenated as one Markdown file, for agents that want everything in one fetch.
- Authoring rules that make docs agent-consumable (already partly in rules): clear H1-H3 hierarchy, self-contained sections (no "as described above"), stable descriptive headings (anchors), examples before abstractions.
- Honesty: llms.txt is a COMMUNITY convention, not a W3C/IETF standard, with no enforcement; it does little for ChatGPT-search citations but real work in the agentic/IDE layer. Position it for client docs sites that developers' agents will consume, not as an SEO play.
