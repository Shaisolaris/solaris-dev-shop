# WordPress Master - Depth pass 2026-06-13 (methodology only, license-safe, no copy-paste)

## 1. ACCURACY FIX - Abilities API (core) vs MCP Adapter (separate plugin)
The file treats "WP Abilities API + MCP Adapter" as a single installable thing. Corrected 2026-06-13:
- **Abilities API is now in WordPress CORE** (landed Nov 2025; part of WP 6.9 and WP 7.0). Plugins/themes/core REGISTER abilities; nothing to install for the API itself.
- **MCP Adapter is a SEPARATE plugin (v0.5.0)**, NOT merged to core, kept on the AI team's own release cadence. It BRIDGES registered abilities to MCP (tools/resources/prompts) so MCP clients (the coding agent) can discover + invoke them.
- Optional companion: "Enable Abilities for MCP" plugin gives an admin toggle per ability (control which abilities are exposed).
- Correct setup story: register abilities (core API) -> install the MCP Adapter plugin -> (optionally) toggle exposure -> the coding agent drives WP via MCP. Don't tell a client to "install the Abilities API"; it's core.

## 2. NET-NEW - WordPress 7.0 (ships 2026-05-20) AI Client / PHP AI Client
WP 7.0 ships a core AI Client (PHP AI Client) - a standard surface for making AI model calls from PHP within WordPress. For plugin developers, the trio to learn is now: Abilities API (register capabilities) + MCP Adapter (expose them to agents) + AI Client (call models from PHP). Add to the modern-stack methodology as the third pillar of WP's AI surface.

## 3. REFRESH - WP 6.9 (Dec 2025) performance + Interactivity API
WP 6.9 delivers ~2.8-5.8% (up to 10-15% in optimized setups) faster loads via a new template output-buffer system, minified + inlined stylesheets, and smarter caching. The Interactivity API iteration improved fetch priority and client-side navigation. Recommend baseline-upgrading client sites to 6.9+/7.0 for the free perf win, and lean on the Interactivity API (not front-end React) for client-side reactivity - now with better nav.

## 4. Small-task / diagnostic lane (the build/diagnostics focus)
- QUICK DIAGNOSE (slow/insecure site): WP-CLI + Query Monitor -> check object cache present, autoload size (`wp option list --autoload=on` size), plugin count/age, page-cache singletons, CWV. Report findings ranked by impact; don't rebuild.
- ONE small build task (a block, a CPT, a child-theme tweak): do it directly via WP-CLI / block.json; skip the full modern-stack ceremony.
- FULL build: FSE block theme + theme.json tokens + Interactivity API + (if AI ops) register abilities + MCP Adapter; security + perf hard rules; staging + backups.

## 5. Rendering / execution path (what is wired vs plan-only)
- WIRED when host connects: the WordPress MCP Adapter (host installs the v0.5.0 plugin on the site + registers abilities) lets the coding agent natively create posts, manage taxonomies, install plugins, audit, etc. WordPress.com managed sites use the official a hosted AI connector instead of self-hosting the adapter.
- WP-CLI is the primary execution surface for build/diagnostics; host provides SSH/WP-CLI access (or the wordpress-expert connect flow if available in the environment).
- PLAN-ONLY otherwise: with no MCP/CLI/site access, this employee plans the change and hands the host the connect/CLI steps - never claims a site change it didn't make.
