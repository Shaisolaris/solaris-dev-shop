# Game Designer - Depth pass 2026-06-13 (methodology only, no code bundled)

## 1. Narrative: Yarn Spinner as a documented alternative to ink
ink (inkle, MIT) stays the primary, but Yarn Spinner (YarnSpinnerTool, MIT) is a proven alternative (DREDGE, Night in the Woods) with a more prose-like script syntax and first-class Unity tooling.
- Routing: ink when you want inkle's weave/knots model and the broadest cross-platform runtime (inkjs web, ink-unity-integration); Yarn Spinner when the team prefers a screenplay-style syntax and Unity-centric workflow.
- Same discipline applies to both: narrative state in the narrative tool, gameplay state in the engine, read each other via variables; two meaningful choices > eight cosmetic ones (SDT autonomy). No code bundled.

## 2. Economy / balance design lane (operationalized - the design/economy focus)
Confirmed 2026: there is NO mature permissive-OSS Machinations equivalent (Flowtrix and Arcweave are proprietary/freemium). So the economy lane is a METHODOLOGY, tool-light:
- SIMPLE / LINEAR economy (single currency, fixed shop, linear progression): model it in a SPREADSHEET. Columns = sources, sinks, conversion rates, per-level costs; chart cumulative currency vs cost curve; tune so the player is neither starved nor flooded. Sheets is sufficient and free.
- COMPLEX economy (multiple currencies, feedback loops, gacha/LiveOps, faucets vs drains over time): model with node-based source/drain/converter/feedback logic - CONNECT Machinations.io (commercial) for live simulation, or replicate the same node logic in a spreadsheet/script if no budget.
- ALWAYS define the economy's intended steady state and failure modes (inflation: too many faucets; grind wall: drains > faucets) BEFORE building, and validate against playtest data (playtest > theory).
- Gacha/loot: published rates are a legal requirement in many jurisdictions; cosmetic-only preferred; pay-to-progress kills retention. (Already in rules; reaffirmed as the economy-ethics gate.)

## 3. Small-task lane
- ONE mechanic prototype / system tweak: pillars + MDA one-pager, prototype ugly+playable, playtest. Skip full studio orchestration.
- ONE branching dialogue: author directly in ink (or Yarn Spinner), validate in the editor, hand to the engine employee to wire.
- FULL "command -> playable": the OpenGame orchestration loop (scaffold -> assets -> build -> 3-axis eval -> debug).

## 4. Rendering / execution path (what is wired vs plan-only) - this employee is the DESIGN BRAIN, execution is delegated
- game-designer owns LAYER 3 (design/orchestration). It does NOT itself drive an engine.
- WIRED via other employees: engine execution through unity-developer (CoplayDev/unity-mcp) and unreal-developer (engine bridge); asset gen through the SHARED asset layer (blender-mcp / Tripo / Meshy / ElevenLabs) - host wires once.
- PLAN-ONLY here: ink/Yarn authoring is text the host compiles; economy spreadsheets are produced here; Machinations is CONNECT (commercial, host wires).
- Definition-of-done for any feature = OpenGame 3 axes (Build Health via the engine employee's test loop, Visual Usability via screenshot judged, Intent Alignment vs pillars) - NOT "the code compiles." Screenshot-and-judge is mandatory; never claim it looks/plays right unseen.
