## 4. Rendering / execution path (what is wired vs plan-only) - this domain is heavily execution-dependent
- WIRED (browser-native, no MCP needed): WebXR runs in the user's browser/headset; three.js / A-Frame / Babylon / @react-three/xr are libraries the built site ships. Served over HTTPS.
- ROUTED to unity-developer: live Unity Editor automation (CoplayDev/unity-mcp) - ar-vr does NOT own the engine bridge; it owns the XR layer + the De-Panther export SOP.
- CONNECT for asset prep: blender-mcp (decimate/bake/export) before gltf-transform - host installs; auto-deploy does not.
- HARDWARE-GATED (plan-only until device present): on-device QA requires a real Quest / Vision Pro / ARCore phone; emulator has known gaps (no teleport thumbstick sim). Never sign off XR comfort/perf from emulator alone.
- No image/audio render MCP needed here; the "render" is the live XR session on the target device.
